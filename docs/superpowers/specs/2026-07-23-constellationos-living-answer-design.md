# ConstellationOS — The Living Answer (Phase 1)

**Date:** 2026-07-23
**Status:** Design approved, ready for implementation plan
**Chamber:** `src/pages/Constellation/`

## Purpose

The ConstellationOS answer plate currently reads as "paper mache": six flat,
bordered `<section>` plates stacked on a translucent dark scrim, floating *on
top of* the galaxy rather than living *in* it. The sky itself (nebula gradients,
`feTurbulence` dust, named figures, seeded twinkle, gold lodestar) is already
beautiful; the disconnect between a document and its backdrop is the whole
problem.

This design dissolves the paper cards into a single constellation that lives in
the same sky, in the same star/edge visual language — while keeping the answer
instantly readable and accessible (the Compose contract is emphatic that this is
*the answer*, `role="article"`, honest refusals surfaced as data).

## Phasing (agreed)

The full vision is sequenced, not stacked. Each later phase gets its own
spec → plan → implementation cycle.

- **Phase 1 (THIS SPEC):** the living-constellation answer — a procedurally
  generated hero figure + a de-carded, breathing body. Deterministic SVG + CSS.
  Design principles formalized through SCDL + Compose. **No new runtime deps.**
- **Phase 2 (later):** a three.js / WebGL parallax depth backdrop behind the
  chamber, gated by Compose, degrading to today's SVG sky.
- **Phase 3 (later):** a WASM procedural-constellation kernel (in the repo's
  existing Rust→wasm TurboQuant/manifold idiom) that computes the hero figure's
  geometry. Phase 1's figure law is authored so it can move behind this kernel
  without changing the visual contract.

`math.js` is explicitly **not** adopted: the repo's determinism laws plus the
existing wasm math toolchain already cover the math, and a general expression
library invites exactly the non-determinism VAELRIX Law 6 forbids.

## Goals

- The answer looks like a constellation, not a stack of cards.
- Each element breathes (seeded, slow, unsynchronised motion), reduced-motion
  honoured.
- The hero figure is *generated by rule from the answer's real data* — the shape
  means something, and the same query always draws the same figure (Law 6).
- Design principles (palette, symmetry, glow, spacing) live in SCDL + Compose as
  validated tokens, not scattered CSS hex.

## Non-goals (Phase 1)

- No three.js, no WebGL, no WASM, no `math.js`, no new runtime dependencies.
- No new interactivity (no click-to-expand node map — that form was considered
  and rejected in favour of a readable hero + body).
- No change to reading order, content, or the analysis packet. No backend change.
- No recomputation of phonological or rarity truth on the frontend (see
  Backend-truth compliance).

## Architecture

Unchanged division of labour from the existing Compose pattern
(`ComposeGalaxyBackdrop` / `ConstellationResultShell`): **the packet gates, the
shell paints, and failure stays local.**

```
ConstellationResultShell (contract gate)
  └─ validateComposeScene(createConstellationResultScene())  ── fails ─► PlainResultShell (today's markup, unchanged)
        │ ok
        ▼
     ComposedResultShell
        ├─ HeroFigure           (NEW — the generated constellation; data-compose-part="hero-figure")
        ├─ Masthead             (existing — query identity)
        ├─ Meaning / Sound      (existing bodies, de-carded + breathing)
        ├─ Genome / Verdict     (existing bodies, de-carded + breathing)
        └─ Provenance seal      (existing)
```

The `HeroFigure` is a new plate at the top of the composed shell. When the scene
contract fails validation the shell degrades to `PlainResultShell` exactly as it
does today — the hero figure simply does not render in the plain fallback, so a
broken figure can never take the answer down (PDR §7.8).

## The figure's generation law (the "reaction")

Honours the `WAND_CHEMICAL_STROKE_PROPAGATION` gene: deterministic rule
application, recursive unfolding, no random param jitter, no score-and-pick.
Phonemes are atoms; genome parameters are the reaction conditions.

### Atoms — from `rhymeAstrology.phonemes` + `phraseGenome.syllables`

- Each phoneme is a star node. Consonants render as dot stars; vowels larger;
  **stressed vowels** (ARPAbet trailing `1`/`2`, read via the existing
  `phonemeArc` test) ignite as the **brightest nuclei**.
- Phonemes group into `syllables` **rosettes**: each rosette clusters its
  phonemes around its stressed nucleus. Rosettes chain along a spine, so the
  syllable count is the number of rings — not one flat arc as today.

### Reaction conditions — applied by rule, never sampled

| Packet field | Operator | Effect |
|---|---|---|
| `rhymeAstrology.cadenceFamily` | symmetry operator | each rosette is laid out bilateral / radial-n / spiral (symmetry = replication catalyst) |
| `phraseGenome.schoolHint` | palette selection | picks the SCDL-authored per-school accent palette (material resonance = reagent selection); amethyst fallback when absent |
| `rarity.band / rarity.max` | brightness + color | **rarer burns brighter** AND sets stellar color temperature (see below) |
| `rhymeAstrology.dominantVowelFamily` | spine curvature | front vowels tighten the arc, back vowels broaden it |
| `pageBytecode` | seed | drives **twinkle** phase/duration and the single ignited **lodestar** nucleus — motion and highlight only, never geometry |

**Geometry has no positional jitter.** Node positions are a pure function of the
formula (spine + rosettes + symmetry operator). The seed touches only motion
(twinkle) and the lodestar choice. This satisfies the anti-jitter law strictly:
nothing in the placement is sampled.

### Rarity → stellar color temperature

Lexical rarity is encoded on two axes, both keyed to the **backend** rarity band
(`rarity.band / rarity.max`, normalized 0..1):

1. **Brightness / glow radius** — rarer burns brighter (photonic selection).
2. **Stellar color temperature** — a real OBAFGKM spectral-class ramp:

   | Normalized rarity | Spectral feel | Color |
   |---|---|---|
   | highest (rare) | O / B | blue-white, hot |
   | high | A | white |
   | mid | F / G | yellow-white → yellow |
   | low | K | orange |
   | lowest (common) | M | red, cool |

   Blue = rarer, red = more common — astronomically faithful (color is
   temperature; hot blue stars are rare and massive, cool red stars are common).

The ramp is authored as an SCDL palette and exposed as Compose design tokens, so
it is part of the validated design language rather than scattered hex.

### Gold stays reserved for "the answer"

This UI reserves **gold = the singular answer** (lodestar, evidenced verdict,
seal). That is a *different* rarity from lexical rarity, so the two are kept
separate:

- The **phoneme star field** takes the rarity-**temperature** color (blue…red).
- Stressed-vowel nuclei are the **brightest temperature stars** — not gold.
- **Gold** appears only on the single seeded **lodestar** nucleus and the
  existing evidenced/seal moments.

This preserves "gold = the rare answer" while letting blue mean "rare word."

### Degradation

If `rhymeAstrology` is a degraded channel, the figure regenerates from
graphemes / token count so there is always *a* figure; the existing
`data-state-degraded` flag carries the honest "partial sky" note. If the whole
scene contract fails, `PlainResultShell` renders (no hero figure).

## The breathing body (de-carding the six channels)

- Remove `.constellation-result-plate` borders and scrim panels. Reading text
  lifts off the sky via a soft per-line text-shadow, not a card surface.
- Section overlines swap the roman-numeral pill for a ✦ **star-anchor** (the
  SCDL-authored glyph); a single hairline **spine** runs down the left, wiring
  the anchors into one figure — echoing the sky's constellation edges.
- Gold "answer" moments (evidenced verdict, seal, lodestar) get a **seeded soft
  glow pulse**. Chips become faint star-field pills that twinkle on seeded
  phases.
- Every breathing element uses an extended `twinkleFor` (seeded, slow,
  unsynchronised opacity/glow — never `transform`, which would clobber the SVG
  positioning attributes). **All motion is reduced-motion gated.**

## SCDL + Compose (the design-principle layer)

### Compose

- Add a `hero-figure` part to `RESULT_PARTS` and the anatomy in
  `src/core/compose/migrated/ConstellationResult.ts`.
- Declare the design principles — per-school palette, the rarity spectral ramp,
  symmetry rules, glow curve, spacing — as design tokens (extending
  `RESULT_VISUALS`), validated **before** paint. The painter reads tokens; a
  contract failure falls back to `PlainResultShell`.
- The scene stays a pure function of frozen constants, so its `sourceChecksum`
  never drifts between builds and the answer's *shape* remains golden-testable.

### SCDL

Author the **fixed** visual vocabulary as SCDL v1.1, compiled via
`codex/core/pixelbrain/scdl/scdl.cli.js`:

- `cos-star.scdl` — the canonical 4-point star glyph.
- `cos-sigil-frame.scdl` — an optional ornamental frame the hero figure sits in.
- `cos-palette-<school>.scdl` + the rarity spectral ramp — per-school accent
  palettes and the OBAFGKM temperature ramp.

**Consumption is vector, not raster.** SCDL is canvas-oriented, so we consume the
compiled model's **`fills`** (rendered as SVG polygons) and **`palette`**
(exposed as DTCG design tokens) — *not* a raster blit. The existing `SPARK_PATH`
constant stays as the deterministic fallback if a compiled glyph is unavailable.

**Boundary:** SCDL owns the *invariant* vocabulary (glyph, frame, palettes); the
*per-query arrangement* stays formula-driven SVG for vector crispness. SCDL is
scoped to what it does cleanly (palette/material vocabulary and simple `fills`),
not forced to express per-query generative geometry.

## Determinism & Law 6 compliance

- No `Math.random`, no `Date.now`. Every generated value derives from
  `pageBytecode` via the existing pure hashes (`fnv1a32`, `seededUnit`) in
  `skyChart.js`.
- The seed chooses the *animation route* and the lodestar highlight — never the
  analysis and never the geometry (PDR §7.6–§7.7).
- Same query → same `pageBytecode` → same figure, same twinkle, forever.

## Backend-truth compliance (`BUGPATTERN_COLOR_DRAGON` gene)

The figure reads **backend-confirmed** values straight from the packet — rarity
band, phonemes, stress digits, and `dominantVowelFamily`. It never recomputes
phonological or rarity truth on the frontend. The ARPAbet stress read renders the
digit the backend already emitted; it does not re-derive stress. No fallback path
may recompute vowel-family or rarity truth — the spec states this so future
degraded-channel code is not tempted to.

## Rendering substrate & performance

- SVG + bytecode-seeded CSS. Reuses the sky's `SPARK_PATH`, radial-gradient, and
  filter idioms.
- Filter/glow budget is bounded (the sky already glows acceptably). Any glow cost
  must be verified **headed** on a cool Deck — never headless (headless
  software-rasterizes and hides GPU fill-rate).

## Testing

Extends the existing `compose-constellation-result-*` suite:

- **Golden geometry:** same `pageBytecode` → byte-identical figure geometry
  (deterministic snapshot).
- **Scene validation:** the new `hero-figure` part validates; on forced
  invalidation the shell falls back to `PlainResultShell`.
- **Reduced motion:** no animation properties emitted when reduced motion is set.
- **Degraded channel:** `rhymeAstrology` absent → figure regenerates from
  graphemes/tokens and `data-state-degraded` is surfaced.
- **Rarity mapping:** rarity band maps to the correct spectral color and
  brightness; gold appears only on the lodestar / evidenced / seal.
- **Backend-truth:** the figure consumes packet stress/vowel-family fields and
  does not recompute them (asserted by feeding mismatched frontend-derivable
  input and confirming the packet value wins).
