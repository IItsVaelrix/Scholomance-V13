# Code of Conduct

Expected of everyone in this project — issues, pull requests, commits, chats,
and reviews.

## The standard

Be rigorous and be decent. Specifically:

- **Argue with the code, not the person.** "This predicate always returns false"
  is a review comment. "You don't understand security" is not.
- **Claims need evidence.** If you say something is broken, show the repro. If
  you say it's fixed, show what you ran. "It should be fine" is not a status.
- **Disagreement is not misconduct.** A rejected design, a reverted commit, and a
  closed PR are normal work. Do not escalate them into a dispute about someone's
  competence or motives.
- **Assume good faith, then verify.** Most broken-looking code is someone's
  reasonable answer to a constraint you haven't read yet. Check the commit
  message and the tests before calling it a mistake.
- **New contributors' time is worth as much as yours.** Answer questions or
  point at the file that answers them. Don't require repo archaeology as an
  entry fee.

## Unacceptable

- Harassment, slurs, and personal attacks.
- Attacking someone's identity, experience level, employer, or tools.
- Publicly shaming an individual for a mistake, including in commit messages,
  PR reviews, and issue threads.
- Deliberately misleading claims of correctness — including in docs and
  comments. A comment asserting a behaviour the code cannot prove is a conduct
  problem, not just a style problem, because the next person will trust it.
- Blocking, doxxing, sustained disruption, or repeating behaviour after being
  asked privately to stop.

## Applying it

Open an issue or PR comment describing what happened and link the offending
comments. Maintainers act proportionally: a note, then a temporary pause on
disputed threads, then removal from the project. Decisions are recorded in the
issue tracker so the reasoning is reviewable rather than private.

Security issues do **not** go through this process — see
[SECURITY.md](SECURITY.md).

## Scope

Applies inside this repository and in any space where someone is representing
it, including chat bridges and conference talks about the code.

This policy is deliberately short and written for this project rather than
adopted from a template, so that every line here is one we actually enforce.
